:::note[核心结论]
ReAct 根据环境反馈动态推进；Plan 先拆解任务再执行。任务的不确定性决定了两者的侧重。
:::

## 两种执行方式

| 模式 | 工作方式 | 更适合的任务 |
| --- | --- | --- |
| ReAct | 思考、调用工具、观察结果，再决定下一步 | 搜索、排障、探索等高不确定性任务 |
| Plan | 先把目标拆解为多个步骤，再按计划推进 | 结构明确、依赖较多的复杂长期任务 |

## ReAct：根据反馈调整动作

ReAct 是“边思考、边行动”的过程。Agent 不会一次性确定全部路径，而是先调用工具，再依据返回结果决定下一步。

```text
思考 → 调用工具 → 观察结果 → 调整下一步
```

这类模式适合搜索和 Debug：一开始往往不知道问题在哪里，工具结果本身会改变后续判断。

## Plan：先形成可执行路线

Plan 模式先把任务拆成多个有序步骤，再逐步执行：

```text
目标 → 任务拆解 → 执行计划 → 分步完成
```

当任务规模较大、步骤依赖明确或需要长期推进时，提前规划能降低遗漏和反复切换方向的成本。

## 如何选择

如果下一步高度依赖外部信息，优先使用 ReAct；如果目标、约束和依赖关系已经相对清楚，优先先做 Plan。实际工作中也常混用：先规划主线，再在每个步骤中用 ReAct 处理未知细节。
